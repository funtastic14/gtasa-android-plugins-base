# Strobo Eyes: Texture-Based Animation Specification

## Product contract

Strobo Eyes has two visual modes:

- **Procedural Eye**: the VLS engine generates the eye geometry and visual components. Preserve independent controls for eyeball, iris, and pupil colors.
- **Custom Eye**: one static PNG is the source artwork. The VLS engine performs texture-coordinate mapping and animation; users must not need separate PNGs for each gaze direction or blink frame.

The three supported eye silhouettes remain:
1. Original / Default / Normal
2. Round
3. Sleepy

Eye motion and eye expression are separate systems. Preserve gaze motion (left, right, up, down, diagonals, idle/scan patterns) and blink. Remove expression presets such as Love, Angry, Sad, Happy, hearts, and similar decorative facial states. Do not remove gaze motion when removing expressions.

## Single-PNG mapping strategy

A conventional flattened PNG does not contain semantic labels for sclera, iris, and pupil. VLS must not pretend it can reliably infer those boundaries from arbitrary artwork. The Custom Eye pipeline therefore uses:

1. A single RGBA PNG as the visual source.
2. A compact per-texture mapping profile (metadata, not another image) describing the eye bounds, eye center, iris/pupil center, and optional iris/pupil radii or normalized regions.
3. A geometry/mask generated by VLS for the selected silhouette.
4. UV remapping over the source image to create gaze displacement and blink deformation. The image is sampled from the same static PNG on every frame.
5. Optional segmentation-assisted independent iris/pupil transforms when metadata identifies those regions. If the supplied art is flattened and no region metadata exists, use bounded UV deformation of the complete eye artwork rather than claiming independent layer movement.

The mapping profile may be embedded in profile JSON or stored as a small sidecar metadata file. It must not require multiple animation-frame PNGs.

## Animation requirements

- Gaze: left, right, up, down, and four diagonals, with bounded displacement and smooth interpolation.
- Blink: close/open using a lid/shutter mask with configurable interval and duration.
- Idle behavior: configurable pause/scan behavior; no expression-state changes.
- Eye Shape: masks the same source artwork and does not change its motif.
- All motion is deterministic from the frame timestamp and profile settings; no per-frame heap allocations.
- Texture cache remains bounded and supports PNG alpha.
- Missing/invalid mapping metadata must fail safely to a documented centered/static fallback.

## Color requirements

Procedural Eye keeps independent eyeball, iris, and pupil color controls. Custom Eye preserves the PNG's authored colors by default. Any optional tint controls must be explicit and must not destroy the source motif or alpha.

## Rendering and performance requirements

- Clamp UV coordinates and clip all sampling to the selected eye mask.
- Preserve alpha; prevent sampling outside the eye artwork.
- Avoid stale pixels, texture smearing, out-of-bounds access, and cross-eye sampling.
- Use bounded texture dimensions and fixed/preallocated cache storage suitable for low-memory Android devices.
- Do not allocate or decode PNG data in the per-pixel/per-frame hot path.
- Keep the existing procedural mode working when no custom texture is selected.

## Acceptance tests

1. All three silhouettes render correctly in Procedural Eye and Custom Eye.
2. One static PNG can be used for all gaze directions and blink states.
3. Gaze reaches left/right/up/down/diagonal targets and returns smoothly to center.
4. Blink closes and reopens without changing the underlying artwork.
5. Iris/pupil/eyeball color controls remain available in Procedural Eye.
6. Custom Eye retains original PNG colors and transparency.
7. No expression presets or expression-generated motifs remain.
8. Invalid PNG/metadata falls back safely and does not crash.
9. Test on low-memory Android hardware for frame-time stability and bounded memory.
10. Build success is necessary but not sufficient; in-game visual tests are required.
